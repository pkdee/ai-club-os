# 0033. Session 에 Docs 의 문서를 참고 자료로 이어 둔다

## 상태

채택. 2026-10-21 에 사용자가 요청했습니다.

## 배경

Docs 에는 회차마다 다루는 내용(예: 2회차 Prompt Engineering, 3회차 Context Engineering)이 문서로 올라갑니다. 그런데 Session 화면에서는 그 회차에 어느 문서를 읽으면 되는지 알 수 없었습니다.

사용자는 "Session에서 참고자료같은 느낌으로 등록되어있는 docs에내용을 import할수있게해줘" 라고 요청했습니다.

## 결정

- Session 개요의 옆 칸에 "참고 자료" 카드를 둡니다. 이어 둔 문서의 제목과 한 줄 소개가 보이고, 누르면 그 문서를 엽니다.
- 문서의 내용을 Session 에 옮겨 적지 않고 문서를 가리킵니다. 문서는 저장소에서 고쳐 배포하므로, 가리켜 두면 늘 고친 내용을 봅니다.
- 운영자가 카드 아래의 칸에서 문서를 골라 "가져오기" 로 잇고, 줄 끝의 버튼으로 뺍니다. Session 을 만들고 고치는 사람이 운영자이기 때문입니다.
- 같은 Club 의 Member 는 모두 봅니다. 이어 둔 것이 없으면 구성원에게는 카드가 보이지 않습니다.

### 데이터

- `session_docs` 테이블에 Session 과 문서의 slug 를 한 줄씩 적습니다. Docs 의 문서는 데이터베이스에 없으므로 slug 로만 가리킵니다.
- slug 의 모양은 데이터베이스가 확인하고, Docs 목록에 있는 문서인지는 앱이 확인합니다.
- 문서가 Docs 목록에서 빠지면 그 줄은 남지만 화면에 보이지 않습니다.
- Session 이나 Club 을 지우면 함께 지워집니다. 이은 사람의 계정을 지우면 이은 사람만 비워집니다.
- 접근 규칙은 Member 가 보고, 운영자가 넣고 지우는 것입니다. 고치는 권한은 없습니다.

### 공용 컴포넌트

- 고르는 칸과 빼는 버튼은 Session 과 Project 를 잇는 화면에 있던 것을 `src/components/link-controls.tsx` 로 옮겨 함께 씁니다. 두 기능이 같은 것을 쓰게 되어 `AGENTS.md` 의 구조 원칙에 따라 공용 영역으로 옮겼습니다. 버튼의 글을 정하는 `actionLabel` 을 더했습니다.

## 결과

- 운영자가 회차를 준비하면서 읽을 문서를 미리 걸어 둘 수 있습니다.
- 문서가 Session 화면에 그대로 펼쳐지지는 않습니다. 문서를 열어 읽습니다.
- 이은 순서대로 보입니다. 순서를 바꾸는 기능은 없습니다.
- 마이그레이션을 적용하기 전에는 운영자에게만 마이그레이션을 적용하라는 안내 카드가 보이고, 구성원에게는 카드가 보이지 않습니다. 나머지 화면은 그대로 동작합니다. 처음에는 운영자에게도 카드를 숨겼는데, 그러면 기능이 어디 있는지 알 수 없다는 사용자의 말을 듣고 바꿨습니다.
- 접근 규칙 시험 `tests/db/99f_session_docs.test.sql` 이 이 규칙을 봅니다.

## 검토할 대안

- **문서의 내용을 Session 에 복사하기**: Session 화면에서 바로 읽습니다. 대신 문서를 고쳐도 Session 에는 옛 내용이 남고, Session 의 소개 글이 아주 길어집니다.
- **`sessions` 에 slug 배열 열을 두기**: 테이블이 하나 덜 생깁니다. 대신 이은 사람과 때를 남길 수 없고, 운영자의 고치기 권한에 열을 하나 더 열어야 합니다. Session 과 Project 를 잇는 `session_projects` 와 같은 모양을 골랐습니다.
- **구성원도 잇게 하기**: 누구나 읽을 문서를 걸 수 있습니다. 대신 회차의 준비물이 운영자의 뜻과 달라질 수 있습니다. Session 을 꾸리는 사람이 운영자라 운영자만 잇게 했습니다.
