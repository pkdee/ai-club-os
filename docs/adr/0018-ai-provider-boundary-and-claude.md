# 0018. AI Provider 를 경계 뒤에 두고 처음에는 Claude 를 쓴다

## 상태

채택. 2026-10-10. `TECH.md` 의 "AI Provider 방향" 을 구체화합니다. AI Insight 의 구조는 `0017-ai-insight-draft-and-publish.md` 에 있습니다.

## 배경

AI Insight 를 만들려면 AI Log 를 읽고 정리할 AI 가 필요합니다. 처음부터 한 회사의 AI 에 제품이 묶이지 않게 하는 것이 이 저장소의 원칙이고, 기록 기능은 AI 가 없어도 온전히 동작해야 합니다. AI Provider 를 들일 때는 무엇을 보내는지 사용자에게 알릴 수 있어야 한다는 요구 사항도 있습니다.

사용자가 AI Provider 로 Claude 를 골랐습니다.

## 결정

- AI Provider 와 제품 기능 사이의 경계는 `src/features/ai-insight/provider/` 에 둡니다. 제품 쪽은 "지킬 것, 자료, 답의 모양을 주면 JSON 을 돌려준다" 는 약속만 압니다.
- 보낼 글은 `prompt.ts` 가 만듭니다. 어느 Provider 를 쓰든 같은 글을 보냅니다. Provider 를 바꾸거나 더할 때는 `provider/` 에 구현을 하나 더하고 `index.ts` 에서 고르게 합니다.
- 처음 구현은 Anthropic 의 Messages API 로 Claude 를 부릅니다. 패키지를 더하지 않고 `fetch` 로 직접 보냅니다.
- 키와 모델은 서버의 환경 변수로 받습니다. `ANTHROPIC_API_KEY` 는 서버에서만 읽고 브라우저로 보내지 않습니다. `AI_INSIGHT_MODEL` 을 비우면 `claude-sonnet-5-5` 를 씁니다. 처음에는 더 큰 모델을 기본값으로 두었다가 같은 날 사용자가 Sonnet 으로 정했습니다.
- 키는 어디에도 드러나지 않게 합니다. 사용자가 보안 사항으로 못 박았습니다.
  - 키를 다루는 `provider/index.ts` 와 `provider/anthropic.ts` 는 `server-only` 로 표시합니다. 브라우저로 가는 코드가 이 파일을 불러오면 빌드가 실패합니다.
  - 키는 Anthropic 으로 보내는 요청의 머리말에만 싣습니다. 돌려주는 값, 화면에 보내는 안내, 데이터베이스에 저장하는 값에는 넣지 않습니다.
  - 오류를 남길 때는 오류를 통째로 남기지 않고 종류와 설명만 남기며, 지금 쓰는 키와 키처럼 생긴 글자를 가린 뒤에 남깁니다.
  - 환경 변수 이름에 `NEXT_PUBLIC_` 을 붙이지 않습니다. 붙이면 값이 브라우저 코드에 박힙니다.
  - 키를 넣는 `.env.local` 은 저장소가 무시합니다. 배포할 때는 배포 서비스의 서버 쪽 환경 변수에 넣습니다.
- 키가 없으면 AI Insight 만 만들 수 없습니다. 화면은 그 사실을 알리고, 기록과 나머지 기능은 그대로 동작합니다.
- 보내는 것은 AI Log 의 제목, 사용한 도구, 시도한 내용, 결과, 배운 점, 다음 행동과 회차의 제목입니다. 작성자의 이름, 이메일, 식별자는 보내지 않습니다. 기록은 번호로만 가리킵니다.
- 한 번에 보내는 글자 수에 한도(12만 자)를 둡니다. 기록이 많으면 기록마다 싣는 양을 줄이고, 그래도 넘으면 오래된 기록부터 뺍니다.
- AI Log 는 사용자가 쓴 글이라 지시처럼 보이는 문장이 들어 있을 수 있습니다. 자료를 표시로 감싸고, 그 안의 지시는 따르지 않게 하며, 기록의 글이 표시를 닫지 못하게 꺾쇠를 바꿔 싣습니다. 답은 정해진 모양으로만 받고 운영자가 확인한 뒤에야 공개됩니다.
- 답의 모양은 API 에 함께 넘깁니다. 그 값을 받지 않는 모델이면 값 없이 한 번 더 보냅니다. 모양은 지킬 것에도 적혀 있어서 어느 쪽이든 같은 방식으로 읽습니다.
- 답은 50초 안에 오지 않으면 그만둡니다. 화면의 서버 동작 제한 시간은 60초로 둡니다.
- 만들기 전에 무엇을 어디로 보내는지 확인 창에서 알립니다. AI Log 를 쓰는 화면에도 운영자가 AI Insight 를 만들 때 내용이 AI 서비스로 보내질 수 있다고 적었습니다.
- 어느 Provider 의 어느 모델이 만들었는지 AI Insight 마다 적어 둡니다.
- 키 없이 흐름을 확인할 수 있도록 시험용 Provider 를 둡니다. `AI_INSIGHT_PROVIDER=mock` 일 때만 쓰고 배포한 환경에서는 무시합니다.

## 결과

- 실제 Claude 를 부르는 것은 키가 없어 이 저장소의 자동 검증으로 확인하지 못합니다. 요청의 모양, 오류에 따른 안내, 답을 읽는 것은 가짜 네트워크를 쓴 단위 시험으로 확인합니다.
- 패키지가 없어 의존성이 늘지 않습니다. 대신 다시 보내기나 형식 변화는 직접 챙겨야 합니다. 지금은 다시 보내지 않고 "잠시 뒤 다시" 라고 안내합니다.
- 기본 모델은 Sonnet 입니다. 환경 변수로 더 작은 모델이나 더 큰 모델로 바꿀 수 있습니다.
- 키가 드러나지 않는지는 세 가지로 확인합니다. 단위 시험이 오류가 나도 돌려주는 값과 남기는 글에 키가 없는지 봅니다. 빌드한 뒤 브라우저로 가는 파일에 환경 변수 이름, 요청 주소, 키 값이 없는지 찾아봅니다. 브라우저 코드가 Provider 를 불러오면 빌드가 실패하는지 봅니다. 2026-10-10 에 세 가지 모두 확인했습니다.
- 운영자가 아닌 사람은 AI 를 부르는 동작을 실행해도 AI 를 부르기 전에 거절됩니다. 로그인하지 않은 요청은 로그인 화면으로 갑니다.
- AI Log 의 내용이 바깥 회사로 나갑니다. 그 회사가 받은 글을 어떻게 보관하는지는 그 회사의 정책을 따릅니다. 운영자와 쓰는 사람에게 보낸다는 사실을 알리지만, 사람마다 동의를 받거나 기록마다 빼는 기능은 없습니다.
- 기록에 적힌 사람 이름이나 연락처는 걸러 내지 않습니다. 작성자 정보만 뺍니다.
- AI 가 거절하거나 모양이 틀린 답을 주면 저장하지 않고 까닭을 알립니다. 운영자가 다시 만들면 됩니다.

## 검토할 대안

- **공식 SDK 패키지를 씀**: 다시 보내기와 형식이 갖춰져 있습니다. 의존성이 하나 늘고, 지금 필요한 것은 요청 하나라서 직접 보내도 충분합니다.
- **AI 를 데이터베이스나 별도 서버에서 부름**: 오래 걸리는 일을 화면과 떼어 놓을 수 있습니다. 운영할 것이 늘고, 지금은 한 번의 요청으로 끝납니다.
- **답을 한 줄씩 받아 화면에 바로 보여 줌**: 기다리는 느낌이 줄어듭니다. 답 전체를 다듬어 저장하는 흐름과 맞지 않고, 운영자만 보는 초안이라 급하지 않습니다.
- **기록에서 사람 이름을 지우고 보냄**: 나가는 개인 정보가 줄어듭니다. 이름을 정확히 찾아내기 어렵고 글의 뜻이 바뀔 수 있습니다.
- **Club 마다 AI Insight 를 켜고 끄게 함**: 원하지 않는 Club 은 기록을 내보내지 않습니다. 지금도 운영자가 누르지 않으면 나가지 않으므로 뒤로 미뤘습니다.
