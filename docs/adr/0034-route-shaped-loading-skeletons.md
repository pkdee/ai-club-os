# 0034. 불러오는 동안 주소로 고른 화면 모양의 자리 표시를 보여 준다

## 상태

채택. 2026-10-21 에 사용자가 요청했습니다.

## 배경

사용자는 "클럽내에서 Docs로 이동하거나 docs에서 새로고침을하게되면 본문이 늦게뜨고 사이드바 (시작하기, Prompt Engineering 같은 주제가있는부분)이 먼저나오게되고있어 고로 전체적으로 스켈레톤 다시 점검 및 설정하고 반응형적용해(pc, 노트북, 모바일, 테블릿 등)" 라고 요청했습니다.

살펴보니 문제는 세 가지였습니다.

- **Docs 로 들어갈 때 목록만 보임.** 메뉴의 Docs 는 `/docs` 를 가리켰습니다. 그 화면은 Club 을 읽은 뒤 첫 문서로 다시 보냅니다. 다시 보내는 동안 문서 목록은 그려지고 본문 자리는 비어 있었습니다. 실험 경로를 만들어 재 보니 목록만 보이는 시간이 약 2.5초였습니다.
- **어느 화면에서나 같은 모양의 자리 표시.** `loading.tsx` 는 Club 안쪽에 하나, 루트에 하나 있었고 둘 다 제목과 카드 세 장의 같은 모양을 그렸습니다.
  - Club 의 `loading.tsx` 는 그 아래 모든 화면을 덮습니다. 그래서 Session 상세로 들어갈 때 머리말과 탭 자리까지 카드 모양이 보였습니다.
  - 처음 Club 에 들어오거나 새로고침하면 Club 의 layout 이 사용자와 Club 을 읽는 동안 루트의 `loading.tsx` 가 보입니다. 이것은 Sidebar 없는 Club 밖 화면의 틀이라, 틀이 들어오며 화면이 크게 움직였습니다.
- **반응형의 빈틈.**
  - 넓은 화면에서 Sidebar 가 내용과 함께 올라가 알림과 설정이 화면 맨 아래로 밀렸습니다.
  - 아주 넓은 화면에서 본문이 1500px 넘게 늘었습니다.
  - AI Log 의 찾는 줄에서 어떤 폭에서는 정렬 칸만 다음 줄에 혼자 남았습니다.

Next.js 의 `loading.tsx` 는 같은 폴더의 layout 안에서 그 아래의 화면과 layout 을 Suspense 로 감쌉니다. 같은 폴더의 layout 은 감싸지 않습니다(`node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/loading.md`). 그리고 `loading.tsx` 는 주소를 받지 못합니다.

## 결정

### Docs

- 메뉴와 개요의 Docs 카드는 처음부터 목록의 첫 문서를 가리킵니다(`docsHref`). 메뉴는 `/docs` 아래의 어느 문서에서도 선택된 것으로 봅니다(`match`).
- `/docs` 로 직접 들어와도 첫 문서로 보내는 동작은 그대로 둡니다.
- `docs/loading.tsx` 를 두어 문서를 불러오는 동안 목록은 남기고 본문과 목차 자리에 문서 모양의 자리 표시(`DocSkeleton`)를 그립니다.

### 화면 모양의 자리 표시

- `src/lib/skeleton-route.ts` 의 `appPage(pathname)` 가 주소의 모양만 보고 화면을 고릅니다. 맞는 화면이 없으면 `other` 입니다.
- 세 `loading.tsx` 는 `"use client"` 로 두고 `usePathname()` 으로 주소를 읽어 알맞은 자리 표시를 그립니다.
  - 루트(`src/app/loading.tsx`): Club 안쪽이면 Club 의 틀(`ClubShellSkeleton`)과 그 화면의 자리 표시를 함께 그립니다. 처음 화면, 내 계정, 초대, 발표, 발표 모드도 각자의 모양을 그립니다.
  - Club(`src/app/clubs/[clubId]/loading.tsx`): 틀은 남기고 본문 자리에 그 화면의 자리 표시를 그립니다. Session 상세면 머리말과 탭 자리까지 그립니다.
  - Session 상세(`sessions/[sessionId]/loading.tsx`): 머리말과 탭은 남기고 그 탭의 자리 표시를 그립니다.
- 자리 표시는 주소가 같으면 서버와 브라우저에서 같게 그려집니다. 실험 경로에서 화면을 옮길 때 `usePathname()` 이 새 주소를 돌려주는 것을 확인했습니다.
- 글 한 줄의 자리(`TextSkeleton`)는 줄 높이를 글자 토큰과 같게 두어, 내용이 들어올 때 아래가 덜 밀리게 합니다.
- 운영자에게만 보이는 버튼과 칸은 그리지 않습니다. 자리 표시는 역할을 모르기 때문입니다.
- 공용 부품은 `src/components/page-skeleton.tsx` 에 둡니다. 화면별 조합은 그 화면의 틀을 가진 기능에 둡니다.
  - Club 안쪽: `features/club/components/club-page-skeleton.tsx`
  - 처음 화면: `features/club/components/my-clubs-skeleton.tsx`
  - 상단 막대: `features/auth/components/top-bar-skeleton.tsx`
  - 그 밖: 내 계정은 `account`, 초대는 `member`, 발표는 `presentation` 기능에 둡니다.

### 반응형

- Club 안쪽의 Sidebar 를 화면 높이에 붙여, 내용을 내려도 Club 바꾸기와 알림, 설정이 보이게 합니다.
- Club 안쪽 본문은 좌우 여백을 넣어 85rem(1360px)까지만 넓히고, 남은 자리의 가운데에 둡니다.
- 640px 보다 좁으면 화면 머리말의 버튼을 제목 아래로 내립니다. Session 목록과 처음 화면도 다른 화면과 같은 모양으로 맞췄습니다.
- AI Log 의 찾는 줄에서 Session, 도구, 정렬 세 칸을 한 덩어리로 묶어 함께 줄을 바꿉니다.
- 화면 폭에 따라 열을 나누는 격자에는 기본 한 열(`grid-cols-1`)을 둡니다. 띄어쓰기 없는 긴 주소가 있어도 좁은 화면에서 열이 넓어져 가로로 넘치지 않게 하려는 것입니다.
- Club 개요의 수 카드는 640px 보다 좁을 때 두 장씩 놓습니다. 한 장씩 쌓으면 본문 앞을 네 장이 다 채웠습니다.
- AI Log 쓰기에서 640px 보다 좁으면 저장 버튼을 맨 아래에 둡니다. "이 기록의 쓰임" 을 고른 뒤에 저장하게 하려는 것입니다.
- Docs 의 문서 목록은 좁은 화면에서 옆으로 밀어 보고, 스크롤 막대는 LinkTabs 처럼 감춥니다.

## 결과

- 화면을 옮기거나 새로고침할 때 그 화면을 닮은 자리 표시가 보이고, Club 의 틀은 처음부터 제자리에 그려집니다.
- 화면을 새로 만들거나 주소를 바꾸면 `skeleton-route.ts` 와 그 시험, 자리 표시 조합을 함께 고쳐야 합니다. 고치지 않으면 `other` 가 되어 제목과 카드의 기본 모양이 보입니다.
- 자리 표시는 실제 화면의 class 를 옮겨 적은 것이라, 화면의 모양을 크게 바꾸면 함께 고쳐야 합니다.
- 로그인한 화면은 이 환경에서 브라우저로 열지 못했습니다. 그래서 자리 표시와 반응형은 로그인 없이 열리는 임시 미리 보기 경로에서 실제 컴포넌트에 가짜 값을 넣어 확인했습니다. 확인한 폭은 360, 375, 640, 768, 1024, 1280, 1536, 1920px 입니다.

## 검토할 대안

- **화면마다 `loading.tsx` 를 두고 route group 으로 나누기**: Next.js 가 권하는 모양이고, 미리 가져오기가 화면마다의 자리 표시를 받아 둡니다. 대신 목록 화면을 `(list)` 같은 묶음 폴더로 옮겨야 하는 화면이 다섯 군데이고 파일이 많이 움직입니다. 또 Club 의 layout 이 기다리는 동안 보일 틀은 결국 루트에서 주소로 골라야 합니다.
- **화면 안에 Suspense 를 두고 머리말을 먼저 그리기**: 머리말이 실제 글로 먼저 보입니다. 대신 화면마다 데이터를 읽는 코드를 둘로 나눠야 하고, 그 전까지는 위쪽 `loading.tsx` 의 기본 모양이 먼저 보여 두 번 바뀝니다.
- **`/docs` 를 `next.config.ts` 의 redirects 로 첫 문서에 보내기**: 다시 보내는 사이가 없어집니다. 대신 설정 파일이 Docs 목록을 알아야 합니다. 메뉴와 카드가 첫 문서를 가리키면 평소에는 다시 보낼 일이 없어 그대로 두었습니다.
