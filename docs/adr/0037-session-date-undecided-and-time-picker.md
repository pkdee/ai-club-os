# 0037. Session 의 날짜 미정과 시각 고르기

## 상태

채택. 2026-10-22 에 사용자가 정했습니다. `0004-session-time-in-korea-standard-time.md` 의 "날짜와 시작, 종료 시각을 가진다" 를 넓혀 날짜를 비워 둘 수 있게 합니다. 한국 시간으로 해석하는 것과 하루 안에 끝나는 것은 그대로입니다.

## 배경

운영자는 회차의 주제와 순서를 먼저 정하고 날짜는 나중에 정하는 일이 많습니다. 지금은 날짜와 시작, 종료 시각을 모두 넣어야 Session 을 만들 수 있어서, 아직 정하지 않은 회차는 아무 날짜나 넣어 두거나 만들지 못했습니다.

시각을 넣는 칸은 브라우저의 `type="time"` 이었습니다. 브라우저와 기기마다 모양과 쓰는 법이 다르고, 시작에서 얼마나 걸리는지 보이지 않습니다. 사용자는 Google Calendar 처럼 목록에서 고르는 칸을 원했습니다.

## 결정

### 날짜 미정

- Session 만들기와 수정 창의 날짜 칸 아래에 "날짜 미정" Checkbox 를 둡니다. 켜면 날짜, 시작, 종료 칸이 막히고 시작과 종료 시각을 함께 비워 저장합니다.
- 데이터베이스에서 `starts_at` 과 `ends_at` 을 비울 수 있게 하고, 둘이 함께 있거나 함께 비어 있어야 한다는 check 제약 `sessions_time_both_or_neither` 를 더합니다. 날짜를 정하면 지금처럼 같은 날의 시작보다 종료가 뒤여야 합니다.
- 상태는 오늘, 예정, 종료에 미정(`undecided`)을 더합니다. Badge 는 warning tone 의 "미정" 입니다. 정해야 할 것이 남았다는 뜻이고, 종료의 neutral 과 구분됩니다.
- 어디에 보이는지는 다음과 같습니다.
  - Session 목록: "오늘과 예정" 과 "지난 Session" 사이에 "날짜 미정" 묶음을 둡니다. 만든 순서로 놓입니다. 카드의 날짜 자리는 "날짜 / 미정" 이고 시각 줄은 없습니다.
  - Session 상세: 날짜 줄에 "날짜 미정" 을 적고 시각 줄은 뺍니다. 바로 앞 회차의 다음 행동은 날짜를 정한 회차끼리만 이어서, 미정인 회차에는 보이지 않습니다.
  - Club 개요: 오늘 Session 과 다가오는 Session 에 넣지 않습니다. 평균 출석의 최근 5회차에서 뺍니다. "진행한 Session" 카드의 "예정 N회" 에는 셉니다. 아직 마치지 않은 회차의 수로 보는 것이 가장 단순해서입니다.
  - AI Log 쓰기의 Session 고르기: 날짜를 정한 회차를 최근 것부터 두고, 미정인 회차는 맨 아래에 "날짜 미정" 으로 둡니다. 오늘 열리는 회차로 미리 고르지 않습니다. AI Log 목록의 Session 고르기도 미정인 회차를 맨 아래에 둡니다.
  - 회고: 시작하지 않은 회차로 봐서 쓸 수 없습니다. 데이터베이스의 `private.check_retrospective_target()` 이 이미 그렇게 막습니다.
  - Club 발표: `get_presentation` 이 이미 시작한 회차만 내보내므로 나가지 않습니다.
- 목록은 시작 시각 순서로 읽고, 비어 있는 회차는 맨 뒤에 만든 순서로 둡니다(`nulls last`, `created_at`).

### 시각 고르기

- `src/components/ui/time-picker.tsx` 의 TimePicker 를 둡니다. 이미 설치된 `@base-ui/react` 의 Combobox 위에 만들어서 새 패키지는 없습니다. 칸을 누르면 30분 간격의 목록이 열리고, 고른 시각이 목록 가운데에 옵니다. 고른 것이 없는 시작 칸은 오후 7시 언저리를 먼저 보여 줍니다.
- 종료 칸의 목록은 시작에서 30분, 1시간처럼 30분씩 더한 시각을 그날 안에서만 보여 주고, 옆에 "30분", "1시간 30분", "2시간" 처럼 걸리는 시간을 적습니다.
- 칸에 시각을 바로 적어도 됩니다. "19:10", "1910", "7:10", "오후 7:10", "오후 7시 10분", "7시 반", "7pm" 을 읽습니다. 오전과 오후를 적지 않은 1~11시는 종료 칸에서는 시작보다 뒤인 쪽, 시작 칸에서는 지금 값(없으면 오후 7시)에 가까운 쪽으로 읽습니다. 앞에 0 을 붙인 "07:10" 과 13시 이후는 24시간 표기로 봅니다. 적는 동안 목록은 맞는 시각만 남기고 읽은 시각을 맨 위에 둡니다. Enter 나 칸을 떠날 때 값이 되고, 읽지 못하면 전의 값으로 돌아갑니다.
- 시작을 바꾸면 종료가 같은 길이를 지키며 따라갑니다. 따라간 종료가 그날을 넘으면 종료는 그대로 두고 입력 규칙이 알려 줍니다.
- 서버로 보내는 값은 지금처럼 `date`, `startTime`, `endTime` 이고 HH:MM 입니다. 보이는 칸에는 이름을 두지 않고 hidden input 으로 보냅니다. 날짜 미정은 `dateUndecided=1` 입니다. 막은 칸의 값도 보내서, 저장하지 못해 창을 다시 그릴 때 적어 둔 값이 남습니다.
- 날짜는 지금처럼 브라우저의 `type="date"` 입니다.
- 목록을 만들고 글을 읽는 순수 함수는 `src/lib/time-of-day.ts` 에 두고 `time-of-day.test.ts` 가 봅니다. 한국 시간 변환은 지금처럼 `src/features/session/time.ts` 만 합니다.

## 결과

- 운영자가 날짜를 정하기 전에 회차를 만들어 두고, 정해지면 수정에서 날짜와 시각을 적습니다.
- 마이그레이션 `20261022030702_session_date_undecided.sql` 은 `sessions` 하나만 잠그고 다시 실행해도 결과가 같습니다. 적용하기 전에 날짜 미정으로 저장하면 마이그레이션을 적용하라는 안내가 나옵니다. 날짜를 정한 Session 은 적용 전에도 그대로 저장됩니다.
- 시각 칸은 기기마다 같은 모양이고 키보드로도 고릅니다. 화살표로 목록을 움직이고 Enter 로 고르며 Esc 로 닫습니다.
- 접근 규칙 시험 `tests/db/20_sessions.test.sql` 이 한쪽만 비운 Session 을 막는 것을, `99a_retrospectives.test.sql` 이 미정인 회차의 회고를 막는 것을, `98_presentations.test.sql` 이 미정인 회차가 발표에 나가지 않는 것을 봅니다.
- 30분 간격이 아닌 시각(예: 19:10)은 적어서 넣습니다. 목록에는 그 시각이 제자리에 끼어 보입니다.

## 검토할 대안

- **날짜만 비우고 시각은 남기기**: 시각만 정해진 회차도 있습니다. 대신 날짜 없는 시각을 저장할 곳이 따로 필요하고 오늘, 예정을 나누는 규칙이 복잡해집니다. 사용자가 날짜가 미정이면 시각도 미정으로 정했습니다.
- **먼 미래의 날짜를 넣어 두기**: 데이터베이스를 바꾸지 않습니다. 대신 예정 목록과 다가오는 Session 에 섞여 보이고, 발표와 회고의 규칙이 그 날짜를 진짜로 봅니다.
- **Base UI 의 Autocomplete**: 적은 글을 그대로 받는 데 맞습니다. 대신 고른 값이 없어서 목록을 열 때 지금 시각으로 내려가지 않고, 종료 목록의 기준을 따로 다뤄야 합니다. 고른 값을 가지는 Combobox 에 적은 글을 읽는 것을 더했습니다.
- **브라우저의 `type="time"` 을 그대로 두기**: 구현이 없습니다. 대신 기기마다 모양이 다르고 걸리는 시간을 보여 줄 수 없습니다.
