# 0007. 초대 링크로 Club 에 참여하게 하고 참여는 데이터베이스 함수가 처리한다

## 상태

채택. 2026-10-10.

## 배경

Club 을 만든 사람 말고는 Club 에 들어올 방법이 없었습니다. 초대 방식은 2026-10-08 에 보류했다가 2026-10-10 에 사용자가 초대 링크로, 만료는 7일로 정했습니다.

구현하면서 정해야 했던 것은 다음과 같습니다.

- 아직 Member 가 아닌 사람은 접근 규칙 때문에 `clubs` 와 `members` 를 읽거나 쓸 수 없습니다. 이 사람이 어떻게 초대받은 Club 을 확인하고 Member 가 될지.
- 링크 값을 누가 만들고 어디에 둘지, 새로 만들 때 이전 링크를 어떻게 할지.
- 로그인하지 않은 사람이 링크를 열었을 때 로그인을 마치고 어떻게 그 링크로 돌아올지.

## 결정

- 초대는 `club_invites` 테이블에 Club 마다 하나만 둡니다. 링크 값은 데이터베이스가 무작위로 만들고, 만든 때부터 7일 뒤에 만료됩니다. 앱은 링크 값과 만료 시각을 정하거나 고칠 수 없습니다.
- 새 링크는 이전 행을 지우고 다시 넣어 만듭니다. 그래서 이전 링크는 바로 쓸 수 없게 됩니다.
- 초대 링크는 운영자만 보고, 만들고, 지웁니다. 구성원에게는 보이지 않습니다.
- 링크는 `/join/링크 값` 주소입니다. 열면 Club 이름을 보여 주고, "참여하기" 를 눌러야 참여합니다. 주소를 여는 것만으로는 참여되지 않습니다.
- 미리 보기와 참여는 `public.preview_club_invite`, `public.join_club` 두 함수가 맡습니다. 두 함수는 만든 사람의 권한으로 실행되며, 안에서 로그인 여부와 링크 값, 만료를 직접 확인합니다. 로그인하지 않은 요청은 부를 수 없습니다.
- 참여하면 항상 구성원이 됩니다. 이름과 이메일은 Club 을 만들 때와 같은 규칙으로 Google 계정에서 옮겨 적습니다. 이 규칙은 `private.display_name_from` 한 곳에 둡니다.
- 로그인하지 않은 사람이 보려던 경로는 로그인 화면의 `next` 값으로 넘기고, Google 인증을 다녀오는 동안에는 10분짜리 쿠키에 담아 둡니다. 이 앱 안의 경로만 허용하고 나머지는 버립니다.

## 결과

- 링크를 가진 사람은 누구나 7일 동안 참여할 수 있습니다. 링크가 엉뚱한 곳에 퍼지면 운영자가 새로 만들어 막습니다. 참여 인원 제한이나 운영자의 승인 절차는 없습니다.
- 유효한 링크를 가진 로그인 사용자는 참여하기 전에도 Club 의 이름, 소개, Member 수를 봅니다.
- 링크 값은 운영자가 다시 볼 수 있어야 해서 그대로 저장합니다. 122비트의 무작위 값이라 추측할 수 없습니다.
- 역할을 바꾸거나 Member 를 내보내는 기능은 아직 없습니다. 잘못 들어온 사람을 앱에서 내보낼 수 없습니다.
- 돌아갈 경로를 쿠키에 담으므로 Supabase 의 Redirect URL 설정을 바꾸지 않아도 됩니다. 초대 링크뿐 아니라 Club 안쪽 주소를 로그인 없이 열었을 때도 로그인 뒤 그 주소로 돌아갑니다.
- 접근 규칙과 두 함수는 로컬 Postgres 17 에서 15가지 경우를 손으로 시험했습니다. 앱이 보내는 요청 19가지는 같은 데이터베이스에 PostgREST 를 붙여 시험했고, 돌아갈 경로 확인은 다른 사이트로 보내려는 값을 포함해 13가지를 시험했습니다. 실제 Google 로그인을 거쳐 링크로 돌아오는 흐름은 로컬에서 시험할 수 없어 실제 환경에서 확인해야 합니다.

## 검토할 대안

- **초대 코드를 직접 입력**: 말로 전하기 쉽습니다. 대신 짧은 코드는 추측하기 쉬워 시도 횟수 제한이 필요하고, 화면 설계를 고쳐야 합니다. 사용자가 링크를 골랐습니다.
- **`members` 에 생성 규칙을 두어 직접 넣게 함**: 함수를 노출하지 않아도 됩니다. 하지만 접근 규칙은 사용자가 내민 링크 값을 볼 수 없어서, 링크 없이도 아무 Club 에나 들어올 수 있게 됩니다.
- **링크를 여는 순간 바로 참여**: 한 번 덜 눌러도 됩니다. 하지만 주소를 여는 것만으로 데이터가 바뀌면 미리 보기나 실수로 연 경우에도 참여가 일어납니다.
- **초대 기록을 여러 개 쌓아 두기**: 누가 언제 만든 링크로 들어왔는지 남길 수 있습니다. 지금은 쓸 곳이 없어 Club 마다 하나만 두었습니다.
- **돌아갈 경로를 인증 주소에 붙이기**: 쿠키가 필요 없습니다. 대신 Supabase 의 Redirect URL 허용 목록과 맞지 않으면 로그인 자체가 실패할 수 있습니다.
