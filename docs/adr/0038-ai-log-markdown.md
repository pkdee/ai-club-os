# 0038. AI Log 본문의 Markdown

## 상태

채택. 2026-10-26 에 사용자가 정했습니다.

## 배경

AI Log 본문(시도한 내용, 결과, 배운 점, 다음 행동)은 그냥 글이었습니다. 적은 줄바꿈만 지켜 보여 주고 굵은 글, 목록, 코드, 링크는 나타낼 수 없었습니다. AI Log 에는 프롬프트와 코드, 단계별 시도를 적는 일이 많아서 사용자가 Markdown 을 쓰게 해 달라고 했습니다.

## 결정

### 범위

- 본문 네 칸에만 씁니다. 제목, 댓글, 회고, Session 설명은 그대로 그냥 글입니다.
- 데이터베이스는 바꾸지 않습니다. 적은 글을 그대로 저장하고 보여 줄 때 Markdown 으로 읽습니다. 글자 수 제한(5000자)에는 Markdown 표시도 셉니다.

### 그리는 도구

- `react-markdown` 10.1.0 을 설치하고 Docs 가 쓰던 `remark-gfm` 으로 표, 할 일 목록, 취소선, 각주, 주소 자동 링크를 읽습니다. 사용자가 이미 있던 `unified` 묶음을 직접 감싸는 것 대신 이 패키지를 골랐습니다.
- `remark-breaks` 4.0.0 으로 한 줄을 바꾼 것도 줄바꿈으로 봅니다. Markdown 을 쓰기 전에 적은 기록이 적은 모양 그대로 보이게 하려는 것입니다.
- 물결표 하나(`~글~`)는 취소선으로 읽지 않습니다. "1~2시간" 처럼 물결표를 흔히 쓰는 한국어 글이 엉뚱하게 지워져 보이지 않게 하려는 것입니다.
- 규칙은 `src/lib/markdown.ts`, 글 요소는 `src/components/markdown/markdown.tsx` 에 둡니다.

### 안전

- HTML 은 그리지 않고 적은 글자 그대로 보입니다. `react-markdown` 의 기본 동작입니다.
- 링크와 이미지의 주소는 http, https, mailto 처럼 안전한 것만 남깁니다(`react-markdown` 의 기본). 주소가 지워진 링크는 글만 남습니다. 바깥 링크는 새 탭에서 열고 `noopener noreferrer nofollow ugc` 를 붙입니다.
- 이미지는 http, https 주소만 불러옵니다. 앱 안의 주소를 이미지로 적어 보는 사람의 브라우저가 앱에 요청을 보내게 하지 않으려는 것입니다.

### 바깥 이미지

- 사용자가 본문에 적은 바깥 이미지(`![설명](https://...)`)를 이미지로 보이기로 정했습니다. 보는 사람의 브라우저가 그 서버에서 바로 불러오므로 그 서버는 보는 사람의 IP 주소와 브라우저 정보를 알 수 있습니다. 어느 화면에서 불렀는지는 보내지 않습니다(`referrerPolicy="no-referrer"`). 개인 정보 안내에 적었습니다.
- Project 발표는 로그인하지 않은 사람도 보므로 발표의 본문 이미지도 같습니다. 붙인 이미지(Storage)는 지금처럼 발표에 나가지 않습니다.

### 코드 블록

- 사용자가 Docs 와 같은 모양에 색을 넣기로 정했습니다. Docs 의 `CodeBlock`, `CopyCodeButton`, `codeLanguageLabel` 을 `src/components/` 와 `src/lib/` 로 옮겨 함께 씁니다.
- 저장된 본문은 서버가 그리고(`HighlightedMarkdown`), 언어를 적은 코드 블록에 `@shikijs/rehype` 로 Docs 와 같은 테마의 색을 칠합니다. 그런 블록이 없으면 Shiki 를 부르지 않습니다. 처음 부를 때 색 규칙을 읽느라 시간이 들기 때문입니다. 모르는 언어는 색 없이 둡니다.
- 쓰는 중의 미리 보기는 브라우저에서 그리므로 색이 없습니다. Shiki 를 브라우저로 보내지 않으려는 것입니다.

### 쓰는 칸

- 사용자가 GitHub 댓글처럼 쓰기와 미리 보기 탭, 서식 버튼을 두는 모양을 골랐습니다. `src/components/markdown/markdown-editor.tsx` 의 MarkdownEditor 이고, 탭과 서식 줄은 이미 설치된 `@base-ui/react` 의 Tabs 와 Toolbar 입니다.
- 서식 버튼은 굵게, 기울임, 코드, 링크, 목록, 번호 목록입니다. Cmd 나 Ctrl 과 B, I, E, K 로도 씁니다. 다시 누르면 표시를 걷어 냅니다. 기울임은 `*` 로 감쌉니다. `_` 는 "_글_을" 처럼 한글이 바로 붙으면 기울임으로 읽히지 않습니다.
- 목록 줄에서 Enter 를 누르면 다음 줄에 같은 표시를 잇고, 빈 항목에서 누르면 목록을 끝냅니다. 번호는 세 자리까지만 잇습니다. "2026. 10. 26." 처럼 날짜로 시작한 줄에서 번호가 생기지 않게 하려는 것입니다. 한글을 조합하는 중의 Enter 는 건드리지 않습니다.
- 글을 바꿀 때 브라우저의 `execCommand("insertText")` 를 써서 Cmd+Z 한 번으로 되돌립니다. 막힌 브라우저에서는 값을 직접 바꿉니다. 바꾸는 일은 `src/lib/markdown-edit.ts` 의 순수 함수가 정합니다.
- 미리 보기 중에도 쓰는 칸은 남아 있어 폼이 값을 보냅니다. 필수 칸이 비었는데 미리 보기 탭이면 쓰기 탭을 먼저 열어 브라우저가 그 칸을 가리키게 합니다.
- 본문 칸 아래에 "Markdown 을 쓸 수 있습니다." 를 적습니다.

### 보이는 곳

- AI Log 상세, Project 발표, 발표 모드의 AI Log 한 장: Markdown 으로 그립니다. 본문의 `#` 은 감싼 화면의 항목 이름보다 한 단계 아래 태그가 됩니다(상세 h3, 발표 h5, 발표 모드 h4). 모든 제목을 본문과 같은 크기에 굵기로만 가릅니다.
- AI Log 목록 카드, 한 달 회고의 "적어 둔 다음 행동": Markdown 표시를 벗긴 글만 몇 줄 보여 줍니다.
- AI Log 수정 기록: 적은 글 그대로 보여 줍니다. 무엇을 고쳤는지 보는 곳이기 때문입니다.
- AI Insight 로 보내는 글: 적은 글 그대로 보냅니다. AI 모델은 Markdown 을 읽습니다.
- 한 화면에 본문이 여럿이면 각주의 id 가 겹치지 않게 본문마다 다른 앞 글자를 붙입니다.

## 결과

- 이미 쓴 기록도 Markdown 으로 읽힙니다. 한 줄을 바꾼 것은 그대로지만, 줄 맨 앞의 `- `, `1. `, `# `, `> ` 와 네 칸 들여쓰기, `*글*` 같은 것은 모양이 바뀌어 보일 수 있습니다. "2026. 10. 26." 처럼 숫자와 점으로 시작한 줄은 번호 목록으로 보입니다. 글이 없어지지는 않습니다.
- 서버 코드에 Shiki 가 들어갑니다. 브라우저로 보내는 코드에는 들어가지 않습니다. AI Log 쓰기 화면은 미리 보기 때문에 `react-markdown` 을 함께 받습니다.
- `src/lib/markdown.test.ts` 가 HTML, 주소, 줄바꿈, 물결표, 코드 블록의 언어, 각주 id, 글만 남기기를, `src/lib/markdown-edit.test.ts` 가 서식 버튼과 목록 잇기를 봅니다.

## 검토할 대안

- **이미 있는 `unified` 묶음을 직접 감싸기**: 새로 내려받는 것이 없습니다. 대신 주소 거르기와 HTML 처리를 직접 써야 합니다. 사용자가 `react-markdown` 을 골랐습니다.
- **쓰는 대로 꾸며지는 편집기(Tiptap 등)**: Markdown 을 몰라도 됩니다. 대신 큰 패키지가 들어오고 저장 형식과 수정 기록의 비교가 복잡해집니다.
- **옆에 바로 미리 보기**: 넓은 화면에서 바로 확인합니다. 대신 칸이 좁아지고, AI Log 쓰기 화면은 이미 옆 칸이 있어 자리가 모자랍니다.
- **바깥 이미지를 링크로만 보이기**: 보는 사람의 정보가 바깥 서버로 가지 않습니다. 사용자가 이미지로 보이기를 골랐습니다.
- **코드 블록에 색 없이**: 서버 일이 늘지 않고 미리 보기와 같습니다. 사용자가 색을 넣기로 골랐습니다.
