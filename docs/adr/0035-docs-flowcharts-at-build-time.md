# 0035. Docs 의 흐름도를 Mermaid 글로 쓰고 빌드할 때 SVG 로 그린다

## 상태

채택. 2026-10-21 에 사용자가 요청했습니다.

## 배경

사용자는 결제 흐름을 상자와 화살표로 그린 그림을 보여 주며 "문서에서 사진 방식 처럼 작성할 수 있는건 사진처럼 작성해줘" 라고 요청했습니다. 그림에는 왼쪽에서 오른쪽으로 가는 상자들, 둘로 갈라지는 화살표와 그 위의 글, 두 상자를 감싼 묶음과 그 제목이 있었습니다.

Docs 의 세 문서에는 흐름을 글 목록이나 `A → B` 를 적은 코드 블록으로 설명한 곳이 있었습니다. 순서와 갈래, 되풀이는 그림으로 보면 한눈에 들어옵니다.

조건은 이렇습니다.

- 문서는 저장소의 MDX 이고 빌드할 때 화면이 됩니다(ADR 0031). 그림도 문서 안에 글로 쓰여 고치고 비교하기 쉬워야 합니다.
- 화면 모드(밝게, 어둡게)를 따라야 합니다.
- "마크다운으로 복사" 한 곳에서도 그림의 뜻이 남아야 합니다.
- 패키지는 사용자 승인 없이 더하지 않습니다.

## 결정

- 문서에는 ```` ```mermaid ```` 코드 블록에 Mermaid 의 flowchart 를 씁니다. 받는 것은 그 가운데 일부입니다.
  - 방향 `LR`, `TD`(`TB`, `graph` 도 받음)
  - 상자 `id[글]`, `id["글"]`, 줄 나눔 `<br>`
  - 화살표 `-->`, `-->|글|`, `-- 글 -->`, 한 줄에 이어 쓰기
  - 묶음 `subgraph id [제목]` 과 `end`, 묶음 id 로 잇는 화살표
  - `%%` 주석
- 빌드할 때 세 단계로 그립니다. 새 패키지는 없습니다.
  - `src/features/docs/diagram.mjs` 가 글을 읽습니다. 받지 않는 모양은 몇 번째 줄인지 담아 멈춥니다.
  - `diagram-layout.mjs` 가 자리를 잡습니다.
    - 상자는 처음 상자에서 가장 긴 길의 길이로 칸을 정합니다.
    - 거꾸로 가는 화살표는 따라가는 중인 상자로 돌아가는 것으로 찾아 그림 아래(TD 는 오른쪽)로 돌립니다.
    - 칸 안의 차례는 들어오는 상자들의 자리 평균(barycenter)으로 정하고, 겹치는 상자는 덩어리로 묶어 가고 싶은 자리의 평균에 둡니다. 그래서 갈라지는 상자는 받는 상자들의 가운데에 옵니다.
    - LR 은 같은 칸의 상자 너비를, TD 는 모든 상자 너비를 맞춥니다.
    - 화살표는 한 번 꺾고 모서리를 둥글립니다.
    - 화살표가 다른 상자를 지나가면 멈춥니다. 묶음 안의 상자는 한 칸에 놓이므로 서로 잇지 못합니다.
  - `remark-diagram.mjs` 가 코드 블록을 `<Diagram layout={...} />` 로 바꾸고, `components/diagram.tsx` 가 그 자리대로 SVG 를 그립니다.
- 색은 디자인 토큰을 씁니다. 판은 `muted`, 상자는 `primary` 와 `primary-foreground`, 묶음은 `primary-subtle`, 화살표는 `icon-subtle`, 화살표 글은 `muted-foreground` 입니다. 화면 모드를 따라 바뀝니다.
- 그림은 원래 너비를 넘지 않고, 좁은 화면에서는 80% 까지 줄인 뒤 판 안에서 옆으로 밀어 봅니다. 상자의 글을 이은 한 줄 설명을 `aria-label` 로 둡니다.
- `remark-diagram` 은 `remark-markdown` 뒤에 둡니다. "마크다운으로 복사" 에는 코드 블록이 그대로 남아, Mermaid 를 그리는 곳에 붙이면 같은 그림이 됩니다.
- 세 문서에 그림 일곱 개를 넣었습니다. 쓰는 법과 제한은 `src/content/docs/README.md` 의 "그림" 절에 있습니다.

## 결과

- 그림을 글로 고치고 diff 로 비교할 수 있고, 브라우저에서 내려받는 코드가 늘지 않습니다.
- 받는 문법이 Mermaid 의 일부라, 다른 모양을 쓰면 빌드가 멈춥니다. 원이나 마름모 상자, 점선, 묶음 안의 묶음이 필요해지면 `diagram.mjs` 와 `diagram-layout.mjs` 를 함께 넓혀야 합니다.
- 자리 잡기는 단순한 규칙이라, 화살표가 많이 엇갈리는 그림은 그리지 못하거나 보기 좋지 않을 수 있습니다. 그때는 그림을 둘로 나누거나 사이의 상자를 거쳐 가게 씁니다.
- 글의 너비는 글자의 종류(한글과 전각 문자, 영어 대문자, 소문자와 숫자, 띄어쓰기 등)마다 정한 비율로 어림합니다. 글꼴이 바뀌면 `diagram-layout.mjs` 의 `textWidth` 를 함께 봅니다.
- 시험은 `src/features/docs/diagram.test.ts` 에 있습니다. 보여 준 그림의 예를 그 모양대로 놓는지, 갈래의 가운데 정렬, 겹침, 오류, 플러그인과 복사를 봅니다.

## 검토할 대안

- **mermaid 패키지를 브라우저에서 돌리기**: 문법을 모두 받습니다. 대신 패키지가 크고, 그림이 화면이 열린 뒤에 그려져 자리가 밀리며, 색을 토큰과 화면 모드에 맞추려면 설정이 따로 필요합니다. 패키지도 더해야 합니다.
- **빌드할 때 mermaid-cli 로 SVG 만들기**: 브라우저 코드는 늘지 않습니다. 대신 headless 브라우저가 빌드에 들어가 Vercel 빌드가 무겁고 느려집니다.
- **그림을 이미지 파일로 넣기**: 바로 쓸 수 있습니다. 대신 글을 고칠 때마다 그림을 다시 만들어야 하고, 화면 모드를 따르지 않으며, 복사한 Markdown 에서 뜻이 빠집니다.
- **SVG 를 MDX 안에 손으로 쓰기**: 패키지가 없습니다. 대신 상자 하나를 고쳐도 좌표를 모두 다시 셈해야 해서 문서를 쓰는 사람이 고치기 어렵습니다.
- **dagre, elkjs 같은 자리 잡기 패키지**: 엇갈림이 많은 그림도 잘 놓습니다. 대신 패키지를 더해야 하고, 지금 문서의 그림은 단순한 규칙으로 충분합니다.
