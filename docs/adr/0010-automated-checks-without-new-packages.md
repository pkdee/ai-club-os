# 0010. 접근 규칙과 입력 규칙을 새 패키지 없이 자동으로 검증한다

## 상태

채택. 2026-10-10.

## 배경

요구 사항은 핵심 권한 규칙과 사용자 흐름을 자동으로 검증할 수 있어야 한다고 적고 있습니다. 지금까지는 마이그레이션을 쓸 때마다 로컬 Postgres 에서 손으로 시험하고 결과를 눈으로 읽었습니다. 시험 내용이 저장소에 남지 않아서, 규칙을 고칠 때 예전 규칙이 깨졌는지 다시 확인할 방법이 없었습니다.

2026-10-10 에 사용자가 자동 검증을 넣기로 하고, 도구는 새 패키지를 설치하지 않는 쪽을 골랐습니다.

## 결정

- 명령은 `npm test` 하나입니다. 입력 규칙 시험(`npm run test:unit`)과 접근 규칙 시험(`npm run test:db`)을 차례로 돌립니다.
- **접근 규칙**은 Docker 의 `postgres:17-alpine` 에서 시험합니다. `tests/db/run.sh` 가 빈 데이터베이스에 Supabase 의 최소 대역과 `supabase/migrations/` 의 실제 마이그레이션을 적용하고, `tests/db/*.test.sql` 을 파일마다 새 데이터베이스에서 돌립니다.
- 시험 파일은 사용자를 바꿔 가며 요청을 보내고 결과를 한 줄씩 `ok` 또는 `not ok` 로 남깁니다. 도우미는 `tests/db/support/90_helpers.sql` 에 있습니다. `test.is` 는 값을, `test.throws` 는 거부되는 오류 번호를, `test.affects` 는 바뀐 행 수를 확인합니다.
- Supabase 의 대역(`tests/db/support/00_supabase_stub.sql`)은 `anon`, `authenticated` 역할과 `auth.users`, `auth.uid()` 를 만듭니다. Supabase 처럼 `public` 의 새 테이블과 함수의 권한을 이 역할들에 기본으로 줍니다. 그래서 마이그레이션이 권한을 거두는 것을 빠뜨리면 시험에서 드러납니다.
- 두 운영자가 동시에 서로를 내리는 경우는 연결 두 개가 필요해서 `run.sh` 안에서 따로 시험합니다.
- **입력 규칙**은 Node 24 의 내장 test runner 로 시험합니다. 시험 파일은 대상 파일 옆에 `*.test.ts` 로 둡니다. Node 가 TypeScript 를 바로 읽으므로 빌드 단계가 없습니다.
- `tests/register.mjs` 가 Next.js 가 해 주던 주소 풀이 두 가지를 대신합니다. `@/` 를 `src` 로 바꾸고, 확장자를 뺀 주소에 `.ts` 를 붙입니다.
- 단위 시험은 서버 시간대를 뉴욕으로 두고 돌립니다. 한국 시간 처리가 서버 시간대에 기대지 않는지 매번 확인하려는 것입니다.

## 결과

- 지금 접근 규칙 177건과 입력 규칙 44건을 확인합니다. 마이그레이션이나 규칙 파일을 고치면 `npm test` 로 예전 규칙이 유지되는지 볼 수 있습니다.
- 접근 규칙 시험에는 Docker 가 필요합니다. 처음 한 번 이미지를 받고, 그 뒤에는 10초 안팎이 걸립니다.
- 단위 시험은 Node 24 이상에서만 돕니다. TypeScript 를 바로 읽는 기능과 주소 풀이 기능이 그 버전에 있습니다.
- 자동으로 확인하지 않는 것이 남아 있습니다.
  - 화면에서의 사용자 흐름. 로그인, 초대 링크로 참여하기, 폼 제출 같은 것은 여전히 사람이 눌러 봐야 합니다.
  - 앱이 Supabase 에 보내는 조회 문법. 관계를 따라 읽는 조회나 함수 호출이 틀리면 이 시험은 잡지 못합니다. 지금까지는 PostgREST 를 붙여 손으로 확인했습니다.
  - 대역과 실제 Supabase 의 차이. 대역은 필요한 최소만 흉내 냅니다.
  - 이미 적용한 마이그레이션이 기존 데이터를 채우는 동작.
- React 컴포넌트와 Server Action 은 시험하지 않습니다. 규칙을 화면과 동작에서 떼어 순수한 함수로 두는 지금의 구조를 유지해야 시험할 수 있습니다.

## 검토할 대안

- **Supabase CLI 의 로컬 데이터베이스와 pgTAP**: 실제 Supabase 의 Postgres 이미지를 써서 대역이 필요 없고, Supabase 가 권하는 방식입니다. 대신 큰 이미지를 받아야 하고 pgTAP 문법을 익혀야 합니다. 대역과의 차이가 문제를 일으키면 이쪽으로 옮깁니다.
- **Vitest 설치**: 널리 쓰이고 화면 컴포넌트 시험까지 넓히기 쉽습니다. 지금 시험하는 것은 순수한 함수뿐이라 내장 기능으로 충분했고, 사용자가 새 패키지 없이 하기로 했습니다.
- **Playwright 로 화면 흐름 시험**: 사용자 흐름까지 확인할 수 있습니다. Google 로그인을 대신할 방법과 시험용 Supabase 프로젝트가 먼저 필요합니다.
- **결과를 저장해 둔 파일과 비교**: 시험 파일이 짧아집니다. 대신 무엇을 기대하는지가 시험 파일에 보이지 않고, 오류 문구가 조금만 바뀌어도 깨집니다.
