# 0004. Session 의 시각을 한국 시간으로 고정한다

## 상태

채택. 2026-10-10.

## 배경

Session 은 날짜와 시작, 종료 시각을 가집니다. 시각을 다루려면 입력한 값을 어느 시간대로 해석할지, 그리고 "오늘"이 언제인지를 정해야 합니다. 서버는 배포 환경에 따라 UTC 로 동작하고 브라우저는 사용자의 기기 설정을 따르므로, 아무것도 정하지 않으면 같은 Session 이 보는 곳에 따라 다른 날짜로 보일 수 있습니다. 이 제품은 국내 동아리를 대상으로 합니다.

## 결정

- 시각은 timestamptz 로 저장합니다.
- 입력과 표시는 한국 시간으로만 해석합니다. Club 마다 시간대를 두지 않습니다.
- 한국 시간 변환은 `src/features/session/time.ts` 한 곳에서만 합니다. 서버나 브라우저의 시간대 설정에 기대지 않습니다.
- Session 이 오늘인지, 예정인지, 끝났는지는 한국 시간의 날짜로 나눕니다.
- 한 Session 은 하루 안에 끝나는 것으로 입력받습니다. 종료 시각은 같은 날짜의 시작 시각보다 뒤여야 합니다.

## 결과

- 서버 시간대가 달라도 결과가 같습니다. 시간대를 뉴욕으로 바꾼 상태에서 변환과 입력 규칙 24가지를 시험해 확인했습니다.
- 한국 시간은 일광 절약 시간이 없어 UTC 와의 차이가 항상 9시간입니다. 그래서 변환이 단순합니다.
- 자정을 넘기는 Session 은 입력할 수 없습니다. 필요해지면 종료 날짜를 따로 받도록 바꿔야 합니다.
- 해외 구성원에게도 한국 시간으로 보입니다. 화면의 입력 도움말에 한국 시간 기준임을 적었습니다.
- 다른 시간대를 지원하게 되면 Club 에 시간대 열을 더하고 `time.ts` 가 그 값을 받도록 고치면 됩니다. 저장된 값은 그대로 쓸 수 있습니다.

## 검토할 대안

- **Club 마다 시간대를 저장**: 해외 동아리도 쓸 수 있지만 입력, 표시, "오늘" 판단이 모두 Club 설정을 거쳐야 합니다. 지금은 필요가 없어 택하지 않았습니다.
- **브라우저의 시간대를 따름**: 구현은 가장 쉽지만 서버가 그리는 화면과 브라우저가 그리는 화면이 어긋나고, 기기 설정에 따라 날짜가 달라집니다.
- **날짜와 시각을 글자 그대로 저장**: 시간대 변환이 없어지지만 정렬과 비교를 직접 다뤄야 하고, 나중에 다른 시간대를 지원하기 어렵습니다.
