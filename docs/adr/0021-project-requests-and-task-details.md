# 0021. Project 의 참여 요청과 할 일의 담당자, 기한

## 상태

채택. 2026-10-11. `0019-project-structure-and-participants.md` 에서 미뤄 둔 것을 정합니다.

## 배경

Project 의 첫 단계에서 세 가지를 제가 임의로 두었고 사용자가 다듬기로 했습니다.

- 참여자가 아닌 구성원은 참여자나 운영자에게 따로 부탁해야 들어올 수 있다.
- 할 일에 누가 맡았는지와 언제까지인지가 없다.
- Session 과 Project 가 서로를 가리키지 않는다.

Club 개요에서 내가 참여하는 Project 를 바로 볼 수 없다는 것도 함께 고릅니다.

## 결정

### 참여 요청

- 참여자가 아닌 구성원이 Project 화면에서 참여를 요청합니다. 요청은 `project_join_requests` 에 한 줄로 남습니다.
- 요청은 참여가 아닙니다. 참여자나 운영자가 받아 줘야 참여자가 되고 그때부터 고칠 수 있습니다. 스스로 들어갈 수 없다는 규칙은 그대로입니다.
- 받아 주면 참여자로 넣고 요청을 지웁니다. 거절하면 요청만 지웁니다. 요청한 사람은 스스로 거둘 수 있습니다.
- 요청은 요청한 본인과 그 Project 를 고칠 수 있는 사람에게만 보입니다.
- 거절해도 요청한 사람에게 따로 알리지 않습니다. 다시 요청할 수 있습니다.
- 운영자는 스스로를 참여자로 넣을 수 있어서 요청 버튼을 보여 주지 않습니다.

### 담당자와 기한

- `project_tasks` 에 `assignee_member_id` 와 `due_on` 을 둡니다. 둘 다 비워 둘 수 있습니다.
- 담당자는 한 명이고 그 Project 의 참여자여야 합니다. 데이터베이스의 trigger 가 맡길 때 확인합니다.
- 맡은 사람이 Project 에서 빠져도 맡았던 일에는 그 사람이 남습니다. Club 에서 나가면 맡은 사람만 비워집니다.
- 기한은 시각 없이 날짜만 둡니다. 한국 시간의 오늘보다 앞선 날짜이고 아직 끝내지 않았으면 기한이 지난 것으로 보여 줍니다.
- 기한이 다가오거나 지나도 알림을 보내지 않습니다.

### 이어 보기

- Session 과 Project 를 잇는 테이블은 만들지 않습니다. AI Log 가 둘을 모두 가리키므로 기록을 거쳐 잇습니다.
- Session 개요에는 그 회차의 AI Log 가 묶인 Project 를, Project 화면에는 묶인 AI Log 가 나온 Session 을 기록 수와 함께 보여 줍니다.
- Club 개요에는 내가 참여하는 Project 가운데 끝나지 않은 것을 남은 할 일 수와 함께 세 개까지 보여 줍니다.

## 결과

- 함께하고 싶다는 뜻을 화면 안에서 전할 수 있습니다. 받아 주는 사람이 있어야 한다는 점은 그대로입니다.
- 요청이 들어와도 알림이 없어서 참여자가 Project 화면을 열어 봐야 압니다.
- 할 일을 누가 맡았는지 보입니다. 한 일에 여러 사람을 맡길 수는 없습니다.
- 기록을 하나도 남기지 않은 회차와 Project 는 서로 이어지지 않습니다.
- 접근 규칙 시험 42건이 요청을 남기고 보는 사람, 받고 거절하는 사람, 참여자에게만 맡길 수 있다는 것, 함께 지워지고 비워지는 것을 확인합니다.

## 검토할 대안

- **누르면 바로 참여**: 기다릴 필요가 없습니다. 참여가 곧 고칠 권한이라 누구나 한 번 눌러 남의 Project 를 고칠 수 있게 됩니다.
- **받아 줄 때 요청을 자동으로 지우는 trigger**: 앱이 두 번 요청하지 않아도 됩니다. 기존 테이블에 trigger 를 달아야 해서 적용할 파일이 하나 늘어납니다. 대신 앱이 참여자로 넣을 때 요청을 함께 치우고, 남아 있는 요청은 보여 주지 않습니다.
- **담당자를 여러 명 둠**: 함께 맡은 일을 그대로 담습니다. 연결 테이블이 하나 더 필요하고 화면이 복잡해집니다.
- **Session 과 Project 를 직접 묶는 테이블**: 기록이 없어도 이을 수 있습니다. 누가 묶는지와 언제 푸는지에 대한 규칙이 더 필요합니다.
