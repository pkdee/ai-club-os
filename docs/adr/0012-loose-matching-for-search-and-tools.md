# 0012. 검색과 도구 이름은 띄어쓰기와 대소문자의 차이를 넘어 맞춘다

## 상태

채택. 2026-10-10. 도구 표기를 맞추는 대상은 같은 날 `0013-known-tool-catalog.md` 로 넓혔습니다. `0011-ai-log-search-functions.md` 의 "글자가 그대로 들어 있는지를 봅니다" 와 도구를 정확히 같은 이름으로만 고르던 부분을 바꿉니다.

## 배경

검색을 넣은 직후 두 가지가 걸렸습니다.

- "청크 크기" 로 적은 기록을 "청크크기" 로는 찾지 못했습니다. 한국어는 같은 말을 붙여 쓰기도 띄어 쓰기도 해서 이런 일이 잦습니다.
- 도구 이름이 자유 입력이라 "ChatGPT" 와 "chatgpt" 가 다른 도구로 쌓이고, 고르는 칸에도 따로 나왔습니다.

사용자가 둘 다 해결하자고 했습니다.

## 결정

- 글자를 비교할 때는 대소문자를 없애고 공백을 모두 뺀 값을 씁니다. 데이터베이스에서는 `private.search_key`, 앱에서는 `src/features/ai-log/rules.ts` 의 `toolKey` 가 같은 규칙으로 만듭니다.
- 찾는 글자는 공백으로 나눈 낱말이 모두 들어 있는 기록을 찾습니다. 낱말은 제목, 내용, 도구 이름 가운데 서로 다른 칸에 있어도 됩니다. 낱말 하나가 두 칸에 걸쳐 찾아지지는 않습니다. 낱말은 열 개까지만 씁니다.
- 도구로 고를 때는 비교하는 값이 같은 도구를 쓴 기록이 모두 나옵니다. 이름의 일부만으로는 고르지 않습니다. 이 조건도 `search_ai_logs` 함수가 맡습니다.
- 도구 목록(`club_tool_counts`)은 비교하는 값이 같은 이름을 하나로 합치고, 그 가운데 가장 많이 쓰인 표기를 보여 줍니다.
- 기록을 저장할 때 입력한 도구 이름을 Club 에서 이미 쓰는 표기에 맞춥니다. "chatgpt" 라고 적어도 Club 에서 "ChatGPT" 로 쓰고 있으면 그렇게 저장합니다. 처음 쓰는 도구는 입력한 그대로 둡니다.
- 쓰는 화면의 도구 칸은 Club 에서 쓰는 도구 이름을 적는 동안 보여 줍니다.

## 결과

- 이미 저장된 기록의 도구 표기는 고치지 않습니다. 목록과 고르기에서는 하나로 합쳐 보이지만 기록에는 적은 그대로 보입니다. 그 기록을 다시 저장하면 그때 표기가 맞춰집니다.
- 표기를 맞추는 기준은 가장 많이 쓰인 표기입니다. 처음에 틀린 표기가 자리 잡으면 그 표기로 맞춰집니다. 도구 이름을 한꺼번에 고치는 기능은 없습니다.
- 공백을 모두 빼고 비교하므로 "a b" 와 "ab" 가 같은 것으로 잡힙니다. 서로 다른 도구가 우연히 같아지는 경우는 드물다고 보았습니다.
- 낱말 사이의 관계는 보지 않습니다. 조사가 붙은 말이나 비슷한 말, 오타는 찾지 못합니다.
- 검색은 여전히 그 Club 의 기록을 모두 훑고, 비교하는 값을 기록마다 만듭니다. `0011` 에 적은 대로 느려지면 색인을 둡니다.
- 접근 규칙 시험의 검색 부분을 32건으로 늘렸고, 도구 표기를 맞추는 규칙의 단위 시험을 더했습니다.

## 검토할 대안

- **도구를 별도 테이블로 분리해 고르게만 함**: 표기가 갈릴 일이 없습니다. 대신 처음 쓰는 도구를 등록하는 절차가 생겨 기록이 번거로워집니다. "기록이 먼저다" 원칙과 맞지 않습니다.
- **저장된 기록의 도구 표기를 한꺼번에 고침**: 기록에 보이는 표기까지 통일됩니다. 어느 표기가 맞는지를 사람이 정해야 해서 자동으로 하지 않았습니다.
- **`pg_trgm` 으로 비슷한 글자 찾기**: 오타도 찾습니다. 확장 설치와 색인이 필요하고 한국어에서 결과를 예측하기 어렵습니다.
- **띄어쓰기만 무시하고 낱말 나누기는 하지 않음**: 규칙이 단순합니다. "rag langchain" 처럼 서로 다른 칸의 낱말을 함께 찾을 수 없습니다.
