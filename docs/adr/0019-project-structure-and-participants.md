# 0019. Project 는 누구나 만들고 참여자가 고친다

## 상태

채택. 2026-10-10. v0.3 의 첫 결정입니다. 구현은 2026-10-11 에 마쳤습니다.

## 배경

AI Log 는 한 번의 시도를 적는 기록입니다. 여러 회차에 걸쳐 무언가를 만들 때는 기록이 흩어져서, 무엇을 만들고 있고 어디까지 왔는지 한곳에서 보기 어렵습니다. v0.3 의 목표는 AI Log 와 Session 의 결과를 하나의 Project 로 묶고 진행 과정을 관리하는 것입니다.

사용자가 세 가지를 정했습니다. Member 는 누구나 Project 를 만들고, 그 Project 의 참여자가 고친다. 운영자는 모든 Project 를 고치고 지운다. 첫 단계에는 AI Log 묶기, 참여자, 결과물 링크, 할 일 목록을 넣는다. AI Log 하나는 Project 하나에만 속한다.

## 결정

- Project 는 `projects` 테이블에 둡니다. 이름, 목표, 진행 상태를 가집니다. 진행 상태는 준비, 진행 중, 완료 세 가지이고 만들면 준비입니다.
- 참여자는 `project_members`, 결과물 링크는 `project_links`, 할 일은 `project_tasks` 에 따로 둡니다. 세 테이블 모두 `(project_id, club_id)` 로 Project 를 가리켜서 다른 Club 의 것과 섞일 수 없습니다.
- Club 의 Member 는 그 Club 의 Project 를 모두 봅니다. AI Log 와 같은 공개 범위입니다.
- Member 는 누구나 Project 를 만듭니다. 만든 사람은 데이터베이스가 첫 참여자로 넣습니다.
- 고치는 사람은 그 Project 의 참여자와 그 Club 의 운영자입니다. 이름, 목표, 진행 상태, 할 일, 결과물 링크, 참여자를 고칩니다.
- 참여자는 참여자와 운영자가 넣습니다. 참여자가 아닌 구성원이 스스로 들어갈 수는 없습니다. 빠지는 것은 누구나 스스로 할 수 있습니다.
- 지우는 사람은 만든 사람과 운영자입니다. 참여자라도 만든 사람이 아니면 지우지 못합니다. 지우면 참여, 링크, 할 일은 함께 지워지고, 묶여 있던 AI Log 는 `0015-delete-rules.md` 와 같은 생각으로 연결만 끊긴 채 남습니다.
- AI Log 는 `ai_logs.project_id` 한 열로 Project 하나에 묶습니다. 묶는 것은 그 기록의 작성자가 하고, 자기가 참여하는 Project 에만 묶을 수 있습니다. 묶을 때와 다른 Project 로 바꿀 때만 확인하므로, 참여를 그만둔 뒤에도 이미 묶어 둔 기록의 다른 내용은 고칠 수 있습니다.
- 결과물 링크는 `http://` 와 `https://` 주소만 받습니다. 누르면 실행되는 다른 모양의 주소를 막으려는 것이고, 앱의 입력 규칙과 데이터베이스의 check 제약이 함께 확인합니다. 링크는 새 창으로 열고 연 쪽의 정보를 넘기지 않습니다.
- 할 일은 글과 끝냈는지만 가집니다. 끝낸 시각은 데이터베이스가 적습니다. 담당자와 기한은 두지 않습니다.
- 앱은 한 Project 에 링크 20개, 할 일 100개까지만 넣게 합니다. 데이터베이스에는 이 한도가 없습니다.
- 누가 고칠 수 있는지는 화면이 미리 가려 보여 주지만, 실제 판단은 데이터베이스의 접근 규칙이 합니다.
- 마이그레이션은 두 묶음으로 나눕니다. 새 테이블을 만드는 묶음과 `ai_logs` 를 고치는 묶음입니다. 앱이 켜진 데이터베이스에서 여러 테이블을 한 번에 잠그면 조회와 서로를 기다리다 멈출 수 있어서입니다.
- 마이그레이션을 적용하기 전에도 기존 화면은 그대로 돌아갑니다. Project 화면은 아직 쓸 수 없다고 알리고, AI Log 는 Project 없이 읽고 씁니다.
- 화면은 두 곳입니다. Club 메뉴의 Project 목록과 Project 하나의 화면입니다. AI Log 를 쓰는 화면에는 Project 를 고르는 칸이 생깁니다.

## 결과

- 운영자를 기다리지 않고 누구나 Project 를 시작할 수 있습니다. 대신 비슷한 Project 가 여러 개 생길 수 있고, 정리하는 일은 운영자가 맡습니다.
- 참여자가 아닌 구성원은 읽기만 합니다. 함께하고 싶으면 참여자나 운영자에게 넣어 달라고 해야 합니다.
- 참여자가 모두 빠진 Project 가 생길 수 있습니다. 그때는 운영자만 고칠 수 있습니다. 만든 사람은 참여자가 아니어도 지울 수는 있습니다.
- AI Log 하나를 여러 Project 에 걸칠 수 없습니다. 두 Project 에 모두 해당하는 시도는 하나를 골라야 합니다.
- 다른 사람의 AI Log 를 Project 에 대신 묶어 줄 수 없습니다. 작성자가 직접 묶어야 합니다. 운영자도 마찬가지입니다.
- 참여자를 빼도 그 사람이 묶어 둔 AI Log 는 Project 에 그대로 남습니다.
- 링크는 고칠 수 없어서 바꾸려면 지우고 다시 넣습니다.
- Session 과 Project 는 직접 이어져 있지 않습니다. Session 에서 쓴 AI Log 를 Project 에 묶으면 그 기록을 거쳐 이어집니다.
- 좁은 화면의 아래쪽 메뉴가 여섯 칸이 되어 설정을 위쪽 막대의 버튼으로 옮겼습니다.
- 접근 규칙 시험 78건이 누구나 만드는 것, 참여자와 운영자만 고치는 것, 만든 사람과 운영자만 지우는 것, 스스로 들어갈 수 없는 것, 참여하는 Project 에만 기록을 묶는 것, 다른 Club 과 섞이지 않는 것, 함께 지워지는 것을 확인합니다. 입력 규칙은 단위 시험이 확인합니다.

## 검토할 대안

- **운영자만 만듦**: Project 가 정돈됩니다. 구성원이 스스로 시작하지 못해 운영자가 길목이 됩니다.
- **Member 누구나 모든 Project 를 고침**: 규칙이 단순합니다. 관계없는 사람이 남의 할 일과 링크를 바꿀 수 있습니다.
- **스스로 참여하기**: 넣어 달라고 부탁할 필요가 없습니다. 참여가 곧 고칠 권한이라 누구나 한 번 눌러 고칠 수 있게 되어 참여자만 고친다는 규칙이 뜻을 잃습니다.
- **AI Log 를 여러 Project 에 묶음**: 걸치는 시도를 그대로 담습니다. 연결 테이블과 규칙이 늘고, 기록 하나가 어디에 속하는지 한눈에 보이지 않습니다.
- **할 일을 Project 의 JSON 한 열에 둠**: 테이블이 줄어듭니다. 두 사람이 동시에 다른 할 일을 고치면 한쪽이 덮어써집니다.
- **지운 Project 의 AI Log 도 함께 지움**: 남는 것이 없어 깔끔합니다. 사용자가 쓴 원본 기록이 Project 를 지운 사람의 손에 사라집니다.
