# 0006. AI Log 를 항목이 나뉜 원본 기록으로 두고 작성자를 Member 에 묶는다

## 상태

채택. 2026-10-10.

## 배경

AI Log 는 이 제품의 핵심 Entity 입니다. 구성원이 써 본 도구와 시도한 내용을 남기고, 나중에 AI Insight 와 Project 가 이 기록을 재료로 씁니다. 입력 항목, 공개 범위, 수정 권한은 `docs/REQUIREMENTS.md` 의 잠정 결정을 따릅니다.

테이블을 만들면서 다음을 정해야 했습니다.

- 여섯 개의 입력 항목을 어떤 모양으로 저장할지
- 기록을 Session 에 반드시 묶을지
- 작성자를 무엇으로 가리키고, 목록에서 작성자 이름을 어떻게 읽을지
- Session 이 삭제되거나 Member 가 Club 에서 빠질 때 기록을 어떻게 할지

## 결정

- `ai_logs` 한 테이블에 둡니다. 제목, 시도한 내용, 결과, 배운 점, 다음 행동은 각각 글자 열입니다. 필수는 제목과 시도한 내용입니다.
- 사용한 도구는 글자 배열 열에 둡니다. 10개까지이고 이름은 30자까지입니다. 형식은 check 제약이 `private.is_valid_tool_list` 함수로 확인합니다.
- Session 연결은 선택입니다. `(session_id, club_id)` 묶음으로 `sessions` 를 가리켜서 같은 Club 의 Session 에만 묶을 수 있습니다. Session 이 삭제되면 연결만 비우고 기록은 Club 의 기록으로 남깁니다.
- 작성자는 `author_id` 열에 사용자 식별자로 둡니다. 값은 만들 때 로그인한 사용자로 정해지고 앱이 보낼 수 없습니다. `(club_id, author_id)` 묶음으로 `members` 를 가리켜서 그 Club 의 Member 만 작성자가 될 수 있습니다. 목록은 이 관계를 따라 작성자 이름을 함께 읽습니다.
- Member 가 Club 에서 빠지면 작성자만 비우고 기록은 남깁니다.
- 조회는 같은 Club 의 Member 모두에게 허용합니다. 수정은 작성자 본인만 하고, Session 연결과 내용만 고칠 수 있습니다. 삭제 규칙은 두지 않습니다.
- 고친 시각은 내용이 실제로 바뀌었을 때만 바뀝니다. Session 삭제로 연결이 비워질 때는 바뀌지 않습니다.
- 목록은 최신순으로 20개씩 읽습니다. 더 보기는 주소의 `n` 값을 늘리는 방식이고 한 화면에 200개까지 보여 줍니다.

## 결과

- 탈퇴하거나 계정을 지운 사람의 기록이 작성자 없이 Club 에 남습니다. 화면에는 "탈퇴한 Member" 로 보입니다. 이 기록은 아무도 고칠 수 없습니다. 남기는 것이 맞는지는 삭제 정책과 보존 기간을 정할 때 다시 봅니다.
- 작성자도 자기 기록을 지울 수 없습니다. 삭제 정책이 정해지면 규칙을 추가합니다.
- 고치면 이전 내용은 남지 않습니다. 수정 기록을 남길지는 아직 결정이 필요한 항목입니다.
- 도구 이름은 자유 입력이라 같은 도구가 다른 표기로 쌓일 수 있습니다. 대소문자만 다른 것은 한 기록 안에서 하나로 합치지만 기록 사이에서는 맞추지 않습니다. 도구별 집계를 만들 때 다듬는 방법을 정해야 합니다.
- 입력 항목이 바뀌면 열과 check 제약, `src/features/ai-log/rules.ts`, 쓰기 화면을 함께 고쳐야 합니다.
- 200개를 넘는 오래된 기록은 전체 목록에서 볼 수 없습니다. Session 의 AI Log 탭과 내가 쓴 기록으로는 볼 수 있습니다. 검색과 고르기를 만들 때 해결합니다.
- 접근 규칙은 로컬 Postgres 17 에서 16가지 경우를 손으로 시험했습니다. 앱이 보내는 조회와 저장 13가지는 같은 데이터베이스에 PostgREST 를 붙여 세 사용자로 시험했습니다. 입력 규칙은 25가지를 시험했습니다.

## 검토할 대안

- **내용을 jsonb 한 열에 저장**: 입력 항목을 바꾸기 쉽습니다. 하지만 필수 여부와 길이를 데이터베이스가 막기 어렵고, AI Insight 가 항목별로 읽을 때마다 모양을 확인해야 합니다.
- **도구를 별도 테이블로 분리**: 표기를 하나로 맞추고 집계하기 좋습니다. 지금은 도구를 고르는 목록도 집계 화면도 없어서 택하지 않았습니다.
- **작성자를 `members.id` 로 가리킴**: `attendance` 와 같은 모양이 됩니다. 대신 작성자를 로그인한 사용자로 자동으로 채울 수 없어, 앱이 보낸 값이 본인의 것인지 접근 규칙에서 따로 확인해야 합니다.
- **Member 가 빠지면 기록도 삭제**: 개인의 기록이 깔끔하게 사라집니다. 하지만 Club 이 쌓은 기록이 한 번에 없어지고 되돌릴 수 없습니다. 되돌릴 수 있는 쪽을 기본으로 두었습니다.
- **Session 을 필수로**: 모든 기록이 회차의 맥락을 가집니다. 대신 회차 밖에서 혼자 해 본 실험을 남길 수 없습니다.
